## 备注

当前系统已支持：
- ReAct 监督机制（`supervisor.ts`）：8 条确定性规则（无效 finish → 自然完成 → 循环检测 → 工具连续失败 → 子工单全失败 → 剩余迭代不足 → 子工单部分失败 → 审批等待），通过 `executor.ts` 每轮迭代后执行
- 记忆系统（`memory/`）：`ShortTermMemoryManager` 滑动窗口缓冲 + `LongTermMemoryManager` 向量语义检索 + `MemoryService` 统一门面，已集成到 `executor.ts` 中自动记录交互
- 子工单同步串行编排（`orchestration.ts`）：创建子工单后阻塞式 `await executeAgent`，保证 agent 间依赖顺序
- 循环派单检测（assignee 与触发 agent 相同 / 沿父链路向上遍历）
- assignee 兜底：缺失 assignee、agent 不存在、不在项目成员中均跳过执行并回写系统消息
- 工单状态机：`pending → in_progress → reviewing → completed`，含 `failed` / `blocked`，`executor.ts` 在失败时置 failed 并发射状态事件
- 父子工单联动：子工单完成/失败回写父工单消息
- SSE 分步 UI：`executor.ts` 通过 `onEvent` 透传 thought/action/observation，子工单事件带 `childTicketId` 标识供前端区分渲染
- per-ticket 写入互斥锁（`repository.ts` `withTicketLock`），避免并发回写丢消息
- 工具上下文反推：`resolveToolProjectId` 支持从 `ticketId` 反推 `projectId`
- 文件操作路径安全：`resolveSafePath` 禁止绝对路径与跳出工作目录
- Agent 文件操作限制在项目 `workspace` 目录
- 删除项目时清理 `projects/` 下对应数据
- 前端从项目主页可打开项目目录与工作空间
